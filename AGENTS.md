# AGENTS.md

## Purpose

This document provides context for AI coding assistants working on this repository.

The goal is to ensure every change aligns with the overall vision of the portfolio.

---

# Project Vision

This is **not** a template portfolio.

It is a long-term product whose primary objective is to help recruiters quickly understand:

* my engineering ability
* my technical depth
* my problem-solving process
* my learning mindset
* my personality as a developer

The portfolio should communicate **how I think**, not simply **what I built**.

---

# Primary Audience

Priority order:

1. Recruiters
2. Engineering Managers
3. Technical Interviewers
4. Developers
5. General Visitors

Every design and engineering decision should prioritize these users.

---

# Core Principles

When proposing improvements, prioritize:

* clarity
* storytelling
* usability
* maintainability
* performance
* accessibility

Avoid adding features solely because they are visually impressive.

---

# Design Philosophy

The website should feel:

* professional
* memorable
* modern
* minimal
* technically strong

Animations should guide attention instead of distracting users.

Whitespace is preferred over clutter.

Readable content is preferred over decorative elements.

---

# Engineering Philosophy

Prefer:

* semantic HTML
* modular JavaScript
* reusable components
* scalable architecture
* clean CSS
* maintainable code

Avoid unnecessary dependencies whenever native browser capabilities are sufficient.

---

# Project Presentation

Projects should emphasize:

* the problem
* the solution
* architectural decisions
* challenges
* trade-offs
* measurable outcomes
* lessons learned

Avoid presenting projects as simple image galleries.

Each project should tell a story.

---

# UX Philosophy

The website should encourage visitors to continue exploring.

Look for opportunities to improve:

* curiosity
* engagement
* discoverability
* readability
* interaction quality

Small but meaningful interactions are preferred over large decorative animations.

---

# AI Improvement Priorities

When suggesting improvements, prioritize ideas that would impress recruiters.

Examples include:

* richer project storytelling
* interactive case studies
* architecture diagrams
* before/after comparisons
* measurable project outcomes
* engineering decision timelines
* live demos
* code walkthroughs
* accessibility improvements
* performance optimization

Avoid generic portfolio sections that appear in most templates.

---

# Things to Avoid

Avoid adding:

* unnecessary animations
* heavy JavaScript libraries
* decorative UI without purpose
* duplicate content
* meaningless statistics
* excessive visual effects
* complex code for simple problems

Every addition should have a clear user benefit.

---

# Future Direction

This repository is expected to evolve into a complete personal platform containing:

* Portfolio
* Technical Blog
* Project Case Studies
* Learning Journal
* YouTube Integration
* Interactive Experiments
* Open Source Contributions
* Developer Resources

The architecture should support gradual expansion without requiring major rewrites.

---

# Decision Rule

Before implementing any feature, ask:

* Does this help recruiters better understand the developer?
* Does this showcase engineering ability?
* Does this improve storytelling?
* Does this improve usability?
* Is the implementation maintainable?

If the answer to most questions is **No**, the feature should be reconsidered.

---

# Mission

The mission of this repository is not to become the flashiest portfolio on the internet.

The mission is to become a portfolio that people remember because it clearly demonstrates engineering quality, thoughtful design, and continuous growth.
